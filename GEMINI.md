# Документація та передача проєкту: College Schedule PWA (група 85 ДФКР)

Файл створено для передачі проєкту наступному агенту або розробнику. Він містить повний опис архітектури, бізнес-правил, стану виконання технічного завдання (ТЗ) та інструкції для продовження роботи.

---

## 1. Призначення

**College Schedule** — це сучасний веб-застосунок (PWA) розкладу занять та інтеграції завдань Google Classroom для студентів і викладачів коледжу (базова група: **85 ДФКР**, ВСП «Фаховий коледж електронних приладів ІФНТУНГ»).

#### Основні користувацькі сценарії:
1. **Перегляд розкладу на сьогодні та будь-який день тижня**:
   - Мобільний інтерфейс: зручний пейджер днів зі свайпами (`DayPager`), швидкий вибір дня, показ живої пари в реальному часі (без перевантаженої тижневої сітки на малих екранах).
   - ПК/планшет: повноцінна тижнева сітка (понеділок–п'ятниця) та десктопний режим перегляду дня з єдиним уніфікованим дизайном карток; кнопка закріплення групи (pin) розташована безпосередньо біля селектора групи.
   - Індикатор формату навчання курсу (**Очне / Дистанційне навчання**): автоматичний бейдж режиму навчання залежно від курсу групи та налаштувань адміністратора.
2. **Жива пара (Real-time Lesson)**:
   - Автоматичне визначення поточної пари за часом Europe/Kyiv.
   - Індикатор «ще N хв», прогрес-лінія всередині картки, підсвітка та кнопка підключення до онлайн-дзвінка.
3. **Онлайн-заняття (Google Meet / Zoom / інші платформи) та пари з двома викладачами**:
   - Миттєвий перехід на відеоконференцію в один клік із автоматичним визначенням платформи (`Meet`, `Zoom` або `Онлайн` для інших ресурсів).
   - Для онлайн-занять із активним посиланням пріоритет віддається кнопці відеозв'язку (аудиторія приховується, щоб не дублювати простір).
   - **Пари з двома викладачами (підгрупами)**: кожен викладач відображається у власному рядку зі своєю аудиторією або персональним посиланням на пару праворуч (із фолбеком на загальну аудиторію пари або плейсхолдером `—`).
4. **Інтеграція з Google Classroom**:
   - Автоматична синхронізація завдань викладачів, тем, посилань та матеріалів (із розумним об'єднанням завдань між підгрупами).
   - Два режими роботи:
     - **Без прив'язки пошти**: перегляд загальних завдань групи у спокійних нейтральних сірих тонах без лякання словом «прострочено».
     - **З прив'язаною студентською поштою**: персональний трекінг здачі робіт (зелена позначка «Здано», оцінки викладача, точний підрахунок дедлайнів).
5. **Екран «Завдання» з фільтрами за тижнем, предметом та статусом**:
   - Синхронізований зі розкладом перемикач тижня `‹ 19–25 жовт. · 8 тиждень ›`.
   - Сегмент `[Цей тиждень | Усі]`, фільтри за предметом і статусом виконання, виділена група «З минулих тижнів», інформативні empty-стани («✓ Нічого не горить», «На цьому тижні завдань немає»).

## 2. Стек технологій і версії

### Frontend
- **Framework**: Next.js 14 (App Router)
- **UI / Rendering**: React 18, TypeScript
- **Styling**: Tailwind CSS + Custom CSS Variables Design Tokens
- **Animations & Gestures**: Framer Motion
- **Icons**: Lucide Icons + кастомні оптимізовані SVG
- **PWA**: `next-pwa`, Service Worker (`public/sw.js`), автономний офлайн-режим (`/~offline`)
- **Google Auth**: Google Identity Services (`@google/identity-services`)

### Backend
- **Framework**: FastAPI (Python 3.11+)
- **Database ORM**: SQLAlchemy 2.0 (asyncio) + asyncpg
- **Database**: PostgreSQL
- **Migrations**: Alembic
- **HTTP Client**: HTTPX (асинхронні запити до Google Classroom API та зовнішніх джерел)
- **Auth**: Python-Jose (JWT), Passlib (bcrypt)
- **Background Workers**: Асинхронний циклічний синхронізатор Classroom (`classroom_auto_sync_loop`)

### Тести та контроль якості
- Backend: `pytest` (236 активних тестів + 4 skipped у `backend/tests`)
- Frontend: `npx tsc --noEmit` (сувора типізація), `npm run build` (Next.js production build)

## 4. Дані та API

### Формат запису пари (Lesson)
- `lesson_number`: номер пари (1..5).
- `start_time`, `end_time`: реальний час початку і кінця пари.
- `subject_name`: назва дисципліни.
- `teachers`: масив викладачів (`id`, `name`, `room`, `link`) — підтримує індивідуальну аудиторію та персональне посилання на онлайн-пару для кожного викладача (зокрема при поділі на 2 підгрупи).
- `note`: текст нотатки, де зберігаються посилання на Meet/Zoom, домашні завдання Classroom, теми.
- `is_cancelled`, `is_replacement`: прапорці стану заняття.
- `week_type`: `numerator` (чисельник), `denominator` (знаменник), `both` (щотижня).

### Ключові backend endpoints:
- `GET /api/schedule/day?group_id=...&date=YYYY-MM-DD` (включає розрахунок `learning_mode` для групи)
- `GET /api/schedule/week?group_id=...&start_date=YYYY-MM-DD`
- `GET /api/settings/learning-mode` та `PUT /api/settings/learning-mode`: отримання й оновлення режиму навчання (очно/онлайн) у розрізі курсів (1–4 курс).
- `GET /api/classroom/groups/{group_id}/status`: стан синхронізації групи, час останнього оновлення, список завдань групи.
- `POST /api/classroom/sync`: тригер синхронізації групи викладачем/старостою.
- `POST /api/classroom/user-submissions`: отримання персонального статусу робіт авторизованого студента.

### Google Classroom API Scopes:
- `https://www.googleapis.com/auth/classroom.courses.readonly`
- `https://www.googleapis.com/auth/classroom.coursework.me.readonly`
- `https://www.googleapis.com/auth/classroom.student-submissions.me.readonly`
- `https://www.googleapis.com/auth/classroom.announcements.readonly`

## 6. Дизайн-система

- **Токени кольорів (CSS variables)**:
  - `--bg`: фоновий колір сторінки (`#0b0f19`)
  - `--sys-card` / `--surface`: фон карток (`#131926` або `#16161a`)
  - `--border` / `--sys-border`: рамки елементів (`#1f293d` або `#27272a`)
  - `--sys-accent`: небесно-синій акцент (`#38bdf8`)
  - `--danger`: червоний для прострочених дедлайнів авторизованого користувача (`#ef4444` / `#f87171`)
  - `--warn`: бурштиновий для термінових завдань (`#f59e0b` / `#fbbf24`)
  - `--ok`: смарагдовий для зданих робіт та погоджених станів (`#10b981` / `#34d399`)
- **Типографіка**:
  - Чітка ієрархія, повні назви предметів та ПІБ викладачів без агресивного обрізання, підвищений мінімальний розмір шрифту для читабельності.
  - Час занять завжди захищений від перенесення: `white-space: nowrap`.
- **Тап-цілі та доступність**:
  - На мобільному всі ключові інтерактивні елементи мають мінімальну висоту 44px (`min-h-[44px]`), додані `aria-label` та підтримка `prefers-reduced-motion`.

## 7. Запуск, збірка, тести та деплой

### Команди розробки:
```bash
# Backend (віртуальне середовище у корені репозиторію .venv)
source .venv/bin/activate
cd backend
uvicorn app.main:app --reload --port 8000

# Frontend
cd frontend
npm run dev
```

### Перевірка тестів та збірки (обов'язково перед кожним комітом):
```bash
# 1. Backend tests (з кореня репозиторію)
./.venv/bin/pytest backend/tests

# 2. Frontend typecheck
cd frontend
npx tsc --noEmit

# 3. Frontend production build
npm run build
```

  - `DATABASE_URL`

  - `CORS_ORIGINS`

  - `NEXT_PUBLIC_GOOGLE_CLIENT_ID`

## 9. Відомі проблеми та нюанси

1. **Режим без прив'язки пошти не підтверджений скріншотами (ТЗ 17)**: Логіка м'якої мови (сірий чіп замість червоного ⚠, текст «термін минув N дн. тому», згорнута сіра група «Термін минув» та інформаційний банер групи) реалізована в коді `LessonCard.tsx` та `MobileTasksView.tsx`, проте вона ще не валідована користувацькими скріншотами на реальних сесіях мобільних пристроїв без Google-авторизації.
2. **Прогрес-лінія поточної пари та класи Tailwind (ТЗ 23)**: У `LessonCard.tsx` виправлено клас `rounded-xs` на валідний для Tailwind 3 `rounded-full` та прибрано стороннє неонове світіння для точної відповідності дизайн-токенам (`#3B82F6` / `bg-sys-accent`). Проте рендеринг живої пари на вузьких фізичних екранах телефонів (360–390px) у реальному часі ще потребує візуальної перевірки на живих пристроях.
3. **5-та пара в адмінці та events.py**: Для студентів коледжу діють 4 стандартні пари (1: 09:00–10:20, 2: 10:40–12:00, 3: 12:30–13:50, 4: 14:00–15:20). Однак у коді адмін-панелей (`AdminScheduleEditor.tsx`, `GeneratorPanel.tsx`, `LessonEditor.tsx`) та в `backend/app/routers/events.py:bell_defaults` досі збереглася 5-та пара (`5: 15:30–16:50` / `15:30`). Необхідно уніфікувати слоти в адмін-модулях.
4. **33 дублікати пар у базі даних (import-duplicates.json)**: В аналізі бази даних виявлено 33 точні дублікати для однієї групи (`group_id: 11`, понеділок, 1-ша пара, знаменник `schedule_ids: [49239..49271]`). Це створює ризик аномальних накладань або неправильного підрахунку занять. Необхідно провести дедуплікацію та додати унікальні індекси/констрейнти у міграціях Alembic.
5. **Автоматична синхронізація Google Classroom**:
   - **Клієнтський фоновий авто-синк без popup-вікон**: Для авторизованих студентів/старост реалізовано тихе фонове поновлення через збережені у `localStorage` `access_token` / `refresh_token` та серверний обмін токенів (з фолбеком на `GET /api/classroom/groups/{group_id}/status`), без виклику `tokenClient.requestAccessToken` у фоні. Завдяки цьому вікно Google ніколи не миготить саме по собі при відкритті чи перемиканні вкладки.
   - **Відновлення завдань після перезапуску сервера**: `get_classroom_group_status` автоматично відновлює список завдань групи з `LessonOccurrenceNote`, навіть якщо in-memory кеш очистився після перезапуску контейнера чи деплою.
   - **Серверний 24/7 фоновий авто-синк (з refresh_token)**: Якщо у `.env` (або `fly secrets`) вказано `GOOGLE_CLIENT_SECRET`, система автоматично зберігає `refresh_token` при прив'язці старостою, а фоновий воркер `classroom_auto_sync_loop` кожні 10 хвилин автономно оновлює базу навіть без відкритих браузерів користувачів.
6. **Особливості назв аудиторій при ручному введенні в розклад**: Якщо диспетчер вводить нестандартний текст (наприклад, «спортзал 2 пов.»), функція `formatRoom` автоматично перевіряє префікси (`ROOM_PREFIXES`), щоб не додавати зайве «ауд.».
7. **Автономний Service Worker**: При деплої нових версій фронтенду клієнти отримують оновлення через service worker lifecycle (`skipWaiting`), однак для миттєвого оновлення кешу додано подію `visibilitychange`.

## 10. Архітектурні рішення та їхні причини

1. **Розділення публічного та персонального стану**:
   - Розклад і загальний перелік завдань групи доступні всім студентам публічно без будь-якої авторизації.
   - Персональні дані (здав/не здав, оцінка) зберігаються виключно в клієнтському браузері авторизованого студента і не зберігаються у відкритій БД.
2. **Відображення онлайн-посилань та аудиторій (один і два викладачі)**:
   - Якщо заняття має онлайн-посилання (Google Meet, Zoom або інша платформа), замість аудиторії виводиться чітка кнопка підключення з назвою платформи (`Meet`, `Zoom`, `Онлайн`), щоб уникнути візуального шуму.
   - Коли пару ведуть два викладачі (поділ на підгрупи), кожен викладач має власний рядок із вирівняним праворуч індивідуальним посиланням або аудиторією (з фолбеком на спільну аудиторію пари або `—`), що дозволяє кожній підгрупі бачити свій кабінет чи онлайн-кімнату.
3. **Чому нездане завдання ніколи не зникає**:
   - Якщо дедлайн лабораторної минув 2 тижні тому, але студент її не здав — робота лишається актуальним академічним боргом. Застосунок тримає її у групі «З минулих тижнів», доки викладач або студент не змінить статус на `TURNED_IN`/`RETURNED`.

## 11. Інструкції для наступного агента

1. **Суворий контроль якості перед push**:
   - Завжди запускати `cd frontend && npx tsc --noEmit && npm run build` та `./.venv/bin/pytest backend/tests`.
   - Жоден коміт із помилками збірки не повинен потрапляти в `main`.
2. **Безпека секретів**:
   - Ніколи не комітити реальні ключі, паролі, токени доступу чи персональні адреси електронної пошти. Використовувати виключно змінні середовища.
3. **Збереження бізнес-правил ТЗ**:
   - Не змінювати алгоритми прив'язки завдань, розкладу дзвінків та оформлення статусів без попереднього узгодження з ТЗ.
4. **Оновлення цього файлу**:
   - При реалізації нових доробок або зміні архітектури актуалізувати розділи «Стан робіт» та «Відомі проблеми».
5. **Автоматичний push змін у `main`**:
   - Після внесення змін у репозиторій одразу комітити та пушити їх напряму в гілку `main` (`origin main`) сам, без додаткових питань до користувача.
   - Перед комітом виконати перевірки з розділу 7 (тести та збірка); push виконувати лише якщо вони пройшли.
