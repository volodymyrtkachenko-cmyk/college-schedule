# Документація та передача проєкту: College Schedule PWA (група 85 ДФКР)

Файл створено для передачі проєкту наступному агенту або розробнику. Він містить повний опис архітектури, бізнес-правил, стану виконання технічного завдання (ТЗ) та інструкції для продовження роботи.

---

## 1. Призначення

**College Schedule** — це сучасний веб-застосунок (PWA) розкладу занять та інтеграції завдань Google Classroom для студентів і викладачів коледжу (базова група: **85 ДФКР**, ВСП «Фаховий коледж електронних приладів ІФНТУНГ»).

### Основні користувацькі сценарії:
1. **Перегляд розкладу на сьогодні та будь-який день тижня**:
   - Мобільний інтерфейс: зручний пейджер днів зі свайпами, швидкий вибір дня, показ живої пари в реальному часі.
   - ПК/планшет: повноцінна тижнева сітка (понеділок–п'ятниця) та десктопний режим перегляду дня з 3-зонною структурою пари.
2. **Жива пара (Real-time Lesson)**:
   - Автоматичне визначення поточної пари за часом Europe/Kyiv.
   - Індикатор «ще N хв», прогрес-лінія всередині картки, підсвітка та кнопка підключення до онлайн-дзвінка.
3. **Онлайн-заняття (Google Meet / Zoom)**:
   - Миттєвий перехід на відеоконференцію в один клік (Meet / Zoom).
   - Незалежність аудиторії та онлайн-посилання (навіть при наявності Meet номер аудиторії завжди зберігається).
4. **Інтеграція з Google Classroom**:
   - Автоматична синхронізація завдань викладачів, тем, посилань та матеріалів.
   - Два режими роботи:
     - **Без прив'язки пошти**: перегляд загальних завдань групи у спокійних нейтральних сірих тонах без лякання словом «прострочено».
     - **З прив'язаною студентською поштою**: персональний трекінг здачі робіт (зелена позначка «Здано», оцінки викладача, точний підрахунок дедлайнів).
5. **Екран «Завдання» з тижневим фільтром та режимом «Усі»**:
   - Синхронізований зі розкладом перемикач тижня `‹ 19–25 жовт. · 8 тиждень ›`.
   - Сегмент `[Цей тиждень | Усі]`, виділена група «З минулих тижнів», інформативні empty-стани («✓ Нічого не горить», «На цьому тижні завдань немає»).

## 2. Стек технологій і версії

### Frontend
- **Framework**: Next.js 14 (App Router)
- **UI / Rendering**: React 18, TypeScript
- **Styling**: Tailwind CSS + Custom CSS Variables Design Tokens
- **Animations & Gestures**: Framer Motion
- **Icons**: Lucide Icons + кастомні оптимізовані SVG
- **PWA**: `next-pwa`, Service Worker (`public/sw.js`), автономний офлайн-режим (`/~offline`)
- **Google Auth**: Google Identity Services (`@google/identity-services`)

### Backend
- **Framework**: FastAPI (Python 3.11+)
- **Database ORM**: SQLAlchemy 2.0 (asyncio) + asyncpg
- **Database**: PostgreSQL
- **Migrations**: Alembic
- **HTTP Client**: HTTPX (асинхронні запити до Google Classroom API та зовнішніх джерел)
- **Auth**: Python-Jose (JWT), Passlib (bcrypt)
- **Background Workers**: Асинхронний циклічний синхронізатор Classroom (`classroom_auto_sync_loop`)

### Тести та контроль якості
- Backend: `pytest` (226 тестів)
- Frontend: `npx tsc --noEmit` (сувора типізація), `npm run build` (Next.js production build)

## 4. Дані та API

### Формат запису пари (Lesson)
- `lesson_number`: номер пари (1..5).
- `start_time`, `end_time`: реальний час початку і кінця пари.
- `subject_name`: назва дисципліни.
- `teachers`: масив викладачів (`name`, `room`).
- `note`: текст нотатки, де зберігаються посилання на Meet/Zoom, домашні завдання Classroom, теми.
- `is_cancelled`, `is_replacement`: прапорці стану заняття.
- `week_type`: `numerator` (чисельник), `denominator` (знаменник), `both` (щотижня).

### Ключові backend endpoints:
- `GET /api/schedule/day?group_id=...&date=YYYY-MM-DD`
- `GET /api/schedule/week?group_id=...&start_date=YYYY-MM-DD`
- `GET /api/classroom/groups/{group_id}/status`: стан синхронізації групи, час останнього оновлення, список завдань групи.
- `POST /api/classroom/sync`: тригер синхронізації групи викладачем/старостою.
- `POST /api/classroom/user-submissions`: отримання персонального статусу робіт авторизованого студента.

### Google Classroom API Scopes:
- `https://www.googleapis.com/auth/classroom.courses.readonly`
- `https://www.googleapis.com/auth/classroom.coursework.me.readonly`
- `https://www.googleapis.com/auth/classroom.student-submissions.me.readonly`
- `https://www.googleapis.com/auth/classroom.announcements.readonly`

## 6. Дизайн-система

- **Токени кольорів (CSS variables)**:
  - `--bg`: фоновий колір сторінки (`#0b0f19`)
  - `--sys-card` / `--surface`: фон карток (`#131926` або `#16161a`)
  - `--border` / `--sys-border`: рамки елементів (`#1f293d` або `#27272a`)
  - `--sys-accent`: небесно-синій акцент (`#38bdf8`)
  - `--danger`: червоний для прострочених дедлайнів авторизованого користувача (`#ef4444` / `#f87171`)
  - `--warn`: бурштиновий для термінових завдань (`#f59e0b` / `#fbbf24`)
  - `--ok`: смарагдовий для зданих робіт та погоджених станів (`#10b981` / `#34d399`)
- **Типографіка**:
  - Чітка ієрархія, `break-words`, `line-clamp-2` для довгих найменувань завдань.
  - Час занять завжди захищений від перенесення: `white-space: nowrap`.
- **Тап-цілі**:
  - На мобільному всі ключові інтерактивні елементи мають мінімальну висоту 44px (`min-h-[44px]`).

## 9. Відомі проблеми та нюанси

1. **Затримка оновлення токенів Google Classroom**: Якщо сесія Google Identity на телефоні завершилась, користувачеві може знадобитися повторно натиснути «Прив'язати».
2. **Особливості назв аудиторій при ручному введенні в розклад**: Якщо диспетчер вводить нестандартний текст (наприклад, «спортзал 2 пов.»), функція `formatRoom` автоматично перевіряє префікси (`ROOM_PREFIXES`), щоб не додавати зайве «ауд.».
3. **Автономний Service Worker**: При деплої нових версій фронтенду клієнти отримують оновлення через service worker lifecycle (`skipWaiting`), однак для миттєвого оновлення кешу додано подію `visibilitychange`.

## 10. Архітектурні рішення та їхні причини

1. **Розділення публічного та персонального стану**:
   - Розклад і загальний перелік завдань групи доступні всім студентам публічно без будь-якої авторизації.
   - Персональні дані (здав/не здав, оцінка) зберігаються виключно в клієнтському браузері авторизованого студента і не зберігаються у відкритій БД.
2. **Чому Meet не замінює аудиторію**:
   - У змішаному форматі навчання частина студентів перебуває в аудиторії, а частина (або підгрупа) підключається дистанційно. Приховування аудиторії призводило до дезорієнтації студентів у коледжі.
3. **Чому нездане завдання ніколи не зникає**:
   - Якщо дедлайн лабораторної минув 2 тижні тому, але студент її не здав — робота лишається актуальним академічним боргом. Застосунок тримає її у групі «З минулих тижнів», доки викладач або студент не змінить статус на `TURNED_IN`/`RETURNED`.

## 11. Інструкції для наступного агента

1. **Суворий контроль якості перед push**:
   - Завжди запускати `cd frontend && npx tsc --noEmit && npm run build` та `cd backend && pytest`.
   - Жоден коміт із помилками збірки не повинен потрапляти в `main`.
2. **Безпека секретів**:
   - Ніколи не комітити реальні ключі, паролі, токени доступу чи персональні адреси електронної пошти. Використовувати виключно змінні середовища.
3. **Збереження бізнес-правил ТЗ**:
   - Не змінювати алгоритми прив'язки завдань, розкладу дзвінків та оформлення статусів без попереднього узгодження з ТЗ.
4. **Оновлення цього файлу**:
   - При реалізації нових доробок або зміні архітектури актуалізувати розділи «Стан робіт» та «Відомі проблеми».

## 12. Наступні кроки

1. **P0 (Високий пріоритет)**:
   - Моніторинг стабільності автоматичної фонової синхронізації Classroom на боці сервера під навантаженням.
2. **P1 (Середній пріоритет)**:
   - Розширення фільтрації за викладачами для екрана «Завдання» (можливість переглядати ДЗ лише конкретного викладача).
3. **P2 (Низький пріоритет)**:
   - Додаткові кастомні теми оформлення інтерфейсу та розширені налаштування PWA-сповіщень.
