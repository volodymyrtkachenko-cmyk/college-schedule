# Git Workflow Rules

- Після завершення реалізації кодових змін або виправлень обов'язково:
  1. Прогнати релевантні перевірки якості (`pytest`, `tsc --noEmit`, `node --test tests/*.cjs`, `npm run check:contrast`, `npm run build`).
  2. Автоматично виконати `git add`, `git commit` з інформативним повідомленням у стилі Conventional Commits та `git push origin main` без окремого запиту користувача.
- Якщо задача не змінювала код (відповідь на запитання, дослідження або узгодження плану до затвердження) — не робити самовільних комітів чи пушу.
- Ніколи не комітити секрети, `.env`, дампи БД, тимчасові файли огляду чи службові логи (`code_review.txt`, `.DS_Store`).
