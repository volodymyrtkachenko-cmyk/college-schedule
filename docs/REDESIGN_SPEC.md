# 📋 Технічне завдання (ТЗ): Редизайн вебзастосунку розкладу та адміністративної панелі ДФКР

## Вступ та мета документа
Мета цього документа — зафіксувати вичерпні технічні, функціональні та візуальні вимоги до комплексного редизайну користувацького інтерфейсу публічного розкладу занять та адміністративної диспетчерської панелі Дніпровського фахового коледжу радіоелектроніки (ДФКР).

Документ складено суто на рівні продуктових, архітектурних та UX/UI-стандартів (без включення фрагментів програмного коду), базуючись на глибокому аналізі виявлених дефектів ергономіки, надлишковості візуального шуму, конфліктів мобільної взаємодії та затверджених системних рішень.

## 1. Концепція та архітектура системи

Система складається з двох автономних інтерфейсних контурів. Вони використовують єдину систему візуальних констант (дизайн-токенів), але оптимізовані під принципово різні поведінкові патерни користувачів:

1. **Публічний клієнт (Студентський контур):**
   - **Цільова аудиторія:** Студенти, старости, викладачі в ролі переглядачів.
   - **Пріоритет платформи:** Смартфони та планшети (від 360px), адаптивність для ноутбуків і десктопів.
   - **Основний сценарій:** Швидко дізнатися поточну або наступну пару, аудиторію, отримати пряме посилання на відеоконференцію, переглянути дедлайн домашнього завдання з Google Classroom без зайвих переходів та перезавантажень.

2. **Адміністративна панель (Диспетчерський контур):**
   - **Цільова аудиторія:** Завідувачі відділень, диспетчери розкладу, адміністратори системи.
   - **Пріоритет платформи:** Широкоформатні робочі станції (від 1280px до 4K), з повною адаптацією критичних операцій під планшети та смартфони на випадок екстрених замін.
   - **Основний сценарій:** Швидке внесення оперативних змін у розклад, робота з виїзними бічними панелями (Drawer) без втрати контексту тижня, керування чернетками автоматичної генерації, візуальне блокування доступності викладачів через матричну шахівницю, балансування навчального навантаження.

## 2. Дизайн-система та візуальні стандарти (Foundations)

### 2.1. Колірна палітра (True Black / OLED)
Для забезпечення максимальної енергоефективності на смартфонах з OLED-екранами, високого рівня контрасту в умовах слабкого освітлення (зокрема в укриттях) та візуальної глибини встановлюється сувора багатошарова палітра:

| Роль в інтерфейсі | Візуальний параметр | Опис та правила призначення |
| :--- | :--- | :--- |
| **Полотно (Background)** | Чистий чорний (`#000000` або `#09090B`) | Базовий фон сторінки. Створює абсолютний контраст, позбавляє інтерфейс брудних сірих відтінків. |
| **Поверхня (Surface)** | Темно-сірий графіт (`#121214`), рамка `1px` (`#27272A`) | Картки занять, рядки таблиць, бічна навігація, інформаційні контейнери. Відокремлюється від фону виключно тонкою матовою рамкою. |
| **Підняті елементи (Elevated)** | Освітлений графіт (`#18181B`), рамка `#3F3F46` + глибока м'яка тінь | Виїзні панелі (Drawer), модальні вікна підтвердження, спливаючі меню (Dropdown/Popover), підказки (Tooltips). |
| **Основний акцент (Primary)** | Електричний синій (`#3B82F6`) | Головні цільові дії (створення, збереження форми), активні вкладки навігації, стан фокусу полів введення, виділення поточного дня тижня. |
| **Успіх / Онлайн (Success)** | Смарагдово-зелений (`#10B981`, фон 15% прозорості) | Кнопки швидкого переходу до онлайн-занять (Google Meet, Zoom), індикатор активної діючої версії розкладу, статус синхронізації Classroom, зелена точка онлайн-статусу. |
| **Навчальні маркери (Info)** | Фіолетовий (`#8B5CF6`, фон 15% прозорості) | Інтерактивні лічильники та плашки домашніх завдань (`1 ДЗ`), маркування екзаменаційних сесій, факультативів та консультацій. |
| **Увага / Зміни (Warning)** | Бурштиновий (`#F59E0B`, фон 15% прозорості) | Позначки оперативних разових замін пар, індикатори чернеток генерації, беджі чисельника/знаменника, попереджувальні банери розкладу. |
| **Небезпека (Danger)** | Червоний (`#EF4444`) | Суворо для деструктивних операцій: остаточне видалення запису, відкат (Rollback) публікації, критичні системні помилки. |

### 2.2. Стандарти контролів та типографіки

1. **Єдина висотна сітка контролів:**
   - **Десктоп (від 1024px):** Усі інтерактивні елементи першого порядку (кнопки дій, поля введення, селекти, кнопки-тригери випадаючих списків, сегментовані перемикачі) мають фіксовану висоту `40px`. Це гарантує строгу горизонтальну вісь та усуває візуальний «стрибаючий» шум у хедерах сторінок.
   - **Мобільні пристрої (до 1023px):** Висота контролів збільшується до `44px` відповідно до ергономічних вимог сенсорного вводу (Apple HIG та Material Design guidelines для мінімального тач-таргету).

2. **Стан фокусу (Focus State & Keyboard Accessibility):**
   - Усі інтерактивні поля введення, кнопки та селектори при отриманні фокусу з клавіатури або тапом отримують контрастний подвійний контур електричного синього кольору (`#3B82F6`) зі світловим відступом `2px`.
   - Неприпустимо вимикати контур фокусу без заміни на чіткий контрастний аналог.

3. **Суворе правило деструктивних дій:**
   - Червоний колір (`#EF4444`) заборонено використовувати для кнопок виходу, додавання обмежень, нейтрального очищення форми чи звичайних службових повідомлень.
   - Кнопки «Видалити» або «Відкотити» в таблицях і картках ніколи не повинні мати повну заливку або таку саму візуальну вагу й ширину, як позитивні цільові кнопки («Відкрити», «Зберегти»).
   - У табличних реєстрах операція видалення реалізується через нейтральну графітову іконку смітника, яка набуває червоного акценту виключно при наведенні курсора миші або лонгтапі.

4. **Уніфікація візуальної стилістики кнопок:**
   - Кнопки основних дій стандартизуються за текстовим наповненням без застарілих декоративних піктограм (повне видалення скевоморфної іконки дискети у вікнах навантаження та збереження).
   - Піктограма `+` дозволена виключно для кнопок первинного додавання нової сутності (наприклад: `+ Додати навантаження`, `+ Створити версію`).
   - Кнопки переходу на зовнішні посилання обов'язково маркуються мініатюрною спрямованою стрілкою (наприклад: `Meet ↗`, `Zoom ↗`).

## 3. Публічний клієнт розкладу (Студентський контур)

### 3.1. Верхня панель (App-bar)
Замість дворівневої перевантаженої шапки, яка забирала до 130px вертикального простору екрана смартфона, впроваджується однорівневий компактний App-bar з фіксованою висотою `56px`:

```
+-----------------------------------------------------------------------------------------+
| Лого ДФКР | [ Група: 85  ▾ ]  |  < [Сьогодні] >  [ День | Тиждень ]  |  [★] [Classroom] [⋯]  |
|  (Ліва зона контексту)         |        (Центральна зона - ПК)        |    (Права зона дій)    |
+-----------------------------------------------------------------------------------------+
```

* **Ліва зона (Контекст вибору):**
  - Логотип коледжу `ДФКР` з переходом на домашній стан.
  - Єдиний комбінований селектор контексту: замість двох окремих полів пошуку «Група» та «Викладач» відображається компактна плашка з поточним станом (наприклад: `Група: 85 ▾` або `Викладач: Іванов І.І. ▾`).
  - При кліку на плашку відкривається швидкодіючий пошуковий шар (Search Modal / Popover) із двома вкладками («Групи» та «Викладачі») та автоматичним фокусом у поле швидкого пошуку.

* **Центральна зона (Відображається лише на ПК від 1024px):**
  - Навігатор дат: кнопки перемикання попереднього/наступного періоду та центральна кнопка повернення до поточної дати `< Сьогодні >` (усувається дублювання двох кнопок «Сьогодні» в різних кутках екрана).
  - Сегментований перемикач режиму відображення: `День | Тиждень`.

* **Права зона (Швидкі дії та меню):**
  - Іконка збереження в «Обране» (`★` / `☆`).
  - Компактний індикатор підключення до Google Classroom (на ПК).
  - Кнопка відкриття системного меню додаткових дій `⋯`.

* **Системне меню дій `⋯` (Popover на ПК / Bottom Sheet на мобільних):**
  - Містить другорядні сценарії: «Графік навчального процесу», «Статистика розкладу», мобільний перемикач інтеграції з Google Classroom, а також непомітне текстове посилання «Для працівників» (перехід в адмін-панель).
  - На мобільних пристроях у виїзному меню Bottom Sheet ліквідується дублювання елементів закриття: залишається єдиний стандартний хрестик `✕` у правому верхньому куті шторки або закриття свайпом вниз.

### 3.2. Режими відображення на ПК та мобільних

| Режим / Платформа | Діагностована UX-проблема | Затверджене проектне рішення |
| :--- | :--- | :--- |
| **ПК: Режим «День» (Сьогодні)** | При виборі перегляду одного дня на моніторах 1920px картки розтягувалися на всю ширину або утворювали порожнечу праворуч. | **Двоколонковий адаптивний Dashboard** (центрований контейнер з обмеженням ширини `max-width: 1140px`):<br>• **Ліва колонка (65% ширини):** Вертикальний хронологічний таймлайн пар обраного дня зі статусом поточної пари.<br>• **Права колонка (35% ширини):** Інформаційний віджет тижня (номер тижня, тип: Чисельник/Знаменник), інтерактивний міні-календар місяця та блок активних дедлайнів завдань з Google Classroom. |
| **ПК: Режим «Тиждень»** | Поточний день (наприклад, понеділок) після закінчення пар затемнювався повністю (`opacity: 0.4`), через що виглядав як скасований або святковий/вихідний. | **Контрастна 5-денна сітка колонок (Пн–Пт):**<br>• Поточний день чітко акцентується фірмовою синьою лінією завтовшки `3px` у верхній частині шапки стовпчика.<br>• Загальне затемнення всього стовпчика ліквідується.<br>• Напівпрозорими (`opacity: 0.5`) стають виключно ті індивідуальні картки занять, часовий інтервал яких уже минув на поточний момент. |
| **Мобільний вигляд (Смартфони)** | Іконки експорту розкладу та картинки зливалися з чорним фоном; поле вибору групи конфліктувало за висотою з шапкою. | **Оптимізований мобільний сценарій:**<br>• Зберігається розумний банер автоматичного переходу: якщо всі пари поточного дня завершилися, банер пропонує в 1 клік відкрити розклад на завтра.<br>• Під шапкою розміщується горизонтальна закріплена стрічка табів днів тижня (`Пн 19`, `Вт 20`, `Ср 21`...) з горизонтальним скролом та підтримкою свайпів екрана вліво/вправо для зміни дня.<br>• Усі допоміжні іконки отримують контрастний бекграунд-контейнер `36×36px`. |

### 3.3. Анатомія студентської картки заняття
Картка пари є ключовим інформаційним носієм і базується на модульній 3-рівневій структурі з чітким розділенням даних:

```
+---------------------------------------------------------------------------------+
|  [ 1 ПАРА ]   08:00 – 09:20                       [ 🟢 Google Meet ↗ ] (кнопка) |
|---------------------------------------------------------------------------------|
|  Основи алгоритмізації та програмування                                         |
|  (Повна назва предмету без скорочення, напівжирний шрифт, 16px)                 |
|---------------------------------------------------------------------------------|
|  Коваленко О. П.          |   [ ауд. 215 ]            |   [ 📌 1 ДЗ ▾ ] (бедж)  |
+---------------------------------------------------------------------------------+
|  └──> Розгорнутий блок ДЗ (при кліку на бедж):                                  |
|       "Лабораторна робота №3: Двозв'язні списки. Дедлайн: 23:59"                |
+---------------------------------------------------------------------------------+
```

1. **Верхній рядок (Службовий рівень):**
   - Номер пари у фірмовому кольоровому маркері (Primary Blue для стандартної пари або Warning Amber при заміні).
   - Точний часовий проміжок занять (`08:00 – 09:20`).
   - У правому кутку — велика контрастна кнопка прямого переходу до відеозв'язку (`Google Meet ↗` або `Zoom ↗`) з мінімальною висотою `32px` для запобігання хибним клікам. Якщо пара проходить офлайн, замість кнопки відображається нейтральний бедж `Офлайн`.

2. **Середній блок (Змістовний рівень):**
   - Повна офіційна назва навчальної дисципліни.
   - Використовується напівжирне накреслення (`font-weight: 600`), розмір кегля `16px`.
   - Заборонено обрізання назви предмета однією лінією з трикрапкою (`text-overflow: ellipsis`); текстовий блок вільно переноситься на 2–3 рядки без перекриття сусідніх елементів.

3. **Нижній рядок / Футер картки (Контекстний рівень):**
   - Прізвище та ініціали викладача (при кліку дозволяє переглянути його розклад).
   - Візуальна плашка аудиторії (`ауд. 309` або бедж `Дистанційно`).
   - Інтерактивний бедж домашнього завдання з Google Classroom (наприклад: `📌 1 ДЗ ▾` у фіолетовому Info-кольорі).
   - **Механіка розгортання:** Клік по беджу розкриває вбудований акордеон із описом завдання, вкладеними файлами та дедлайном безпосередньо всередині картки без переходу на інші сторінки.

## 4. Адміністративна панель (Диспетчерський контур)

### 4.1. Навігаційний сайдбар (Admin Shell)
Головний елемент каркаса адмін-панелі має ширину `240px` у розгорнутому стані з можливістю згортання в компактний іконковий режим (`64px`) для збереження робочої зони монітора.

```
+--------------------------------------+
| [ДФКР] Адмін-панель           [ < ]  |
+--------------------------------------+
| РОЗКЛАД                              |
|   • Сітка розкладу                   |
|   • Версії та семестри               |
|   • Графік процесу                   |
|                                      |
| АВТОМАТИЗАЦІЯ                        |
|   • Навчальне навантаження           |
|   • Обмеження викладачів             |
|   • Генерація розкладу               |
|   • Імпорт з КРЕ                     |
|                                      |
| ДОВІДНИКИ                            |
|   • Групи                            |
|   • Викладачі                        |
|   • Предмети                         |
|   • Спеціальності                    |
|   • Користувачі                      |
+--------------------------------------+
| [🟢] Диспетчер 1             [ -> ]  |
|      admin@dkr.dp.ua         (Вихід) |
+--------------------------------------+
```

* **Логічна типізація та групування меню:**
  1. **Розклад:** «Сітка розкладу», «Версії та семестри» (повне об'єднання розрізнених сторінок «Версії» та «Налаштування семестру» в єдиний комплексний екран), «Графік навчального процесу».

  - Повністю ліквідується надлишкова розділювальна плашка `ДОДАТКОВО ▲`, яка в поточному інтерфейсі штучно розривала меню та спричиняла обрізання заголовків до вигляду `Автогенер...`.

  - Ліквідуються масивні прямокутні банери `• 1 онлайн` та широка тривожна червона кнопка `Вийти`.
  - Впроваджується компактний картковий блок користувача: аватар/ініціали, ім'я та пошта адміністратора, мініатюрна смарагдова точка статусу зв'язку (`Online`) та нейтральна міні-іконка виходу з системи праворуч.

### 4.2. Сітка розкладу та механіка редагування (Schedule Editor)

  - У поточному інтерфейсі кнопки «Редагувати» та «⋯» розташовувалися в окремому нижньому рядку кожної комірки таблиці, штучно роздуваючи висоту робочого дня на моніторі.

### 4.3. Модулі автоматизації та генерації

1. **Доступність викладачів (Інтерактивна матриця-шахівниця):**
   - **Поточний стан:** Неефективна форма із трьох випадаючих списків (викладач, день, пара) та деструктивно-червоною кнопкою `+ Додати обмеження`, яка вимагала десятків монотонних кліків.
   - **Нове рішення:** Запроваджується наочна матриця щотижневої зайнятості (Шахівниця 5 робочих днів × 6 пар).
   - **UX-механіка:**
     - Диспетчер обирає викладача через верхнє поле пошуку.
     - Нижче миттєво відкривається сітка, де клік по комірці циклічно перемикає її статус: `Вільний` (темний фон) / `Зайнятий/Недоступний` (штрихований червонуватий бедж).
     - Клік по заголовку дня тижня блокує або розблоковує одразу весь день (методичний день викладача).
     - Кнопка збереження обмежень перефарбовується в стандартний синій колір Primary.

2. **Генерація розкладу (Контроль публікації чернеток):**
   - Усувається дезорієнтуючий глобальний випадаючий селектор `Публікувати у версію`, що розташовувався у верхній шапці сторінки над усіма чернетками.
   - **Нове рішення:** Вибір цільової версії інтегрується безпосередньо в модальне вікно фінального підтвердження, яке відкривається натисканням кнопки `Опублікувати` у рядку конкретно згенерованої чернетки.
   - Диспетчер бачить метрики саме цієї чернетки (відсоток задоволених обмежень, кількість "вікон") і обирає, в яку саме версію семестру її записати.

3. **Версії та налаштування семестру:**
   - **Пріоритетне сортування:** Картка версії зі статусом `• ДІЄ ЗАРАЗ` гарантовано закріплюється першою у списку (крайня ліва на ПК, верхня на мобільних пристроях).
   - **Анатомія картки версії на ПК:** Внутрішні дії розділяються: головна дія `Відкрити розклад` залишається повнорозмірною кнопкою, а вторинні дії вилучаються у випадаюче меню `⋯` (`Параметри`, `Клонувати версію`, `Архівувати`, `Видалити`). Це унеможливлює технічне обрізання напису в кнопці `Параметри`.
   - **Калькулятор семестру:** Блок налаштування початкової дати семестру доповнюється живим прев'ю-блоком розрахунку: диспетчер бачить, який сьогодні розрахунковий номер тижня та який поточний режим (Чисельник чи Знаменник). Дублюючий опис логіки видаляється.

### 4.4. Навчальне навантаження та Довідники (CRUD)

1. **Фільтрація та підсумкова статистика (Summary Bar):**
   - У розділі «Навчальне навантаження» над таблицею поруч із полем швидкого пошуку впроваджуються селектори швидкої фільтрації за `Групою` та `Викладачем`.
   - Додається підсумкова закріплена інформаційна панель (Summary Bar):  
     `Знайдено записів: 142  |  Сума пар на тиждень: 36  |  Всього заплановано годин: 720 год`
   - Це дозволяє диспетчеру моментально перевіряти баланс навантаження без ручного перерахунку рядків.

2. **Оптимізація простору в таблицях довідників:**
   - Для довідників з 2–3 колонками даних («Предмети», «Спеціальності», «Викладачі») встановлюється максимальне обмеження ширини табличного контейнера (`max-width: 960px`) по центру, або додаються інформативні колонки супутніх зв'язків (наприклад, для предмета — кількість закріплених груп та викладачів; для викладача — ставка та закріплені дисципліни).
   - Це ліквідує неестетичну порожнечу в 1000px між назвою сутності зліва та кнопками дій справа.

3. **Нормалізація модальних вікон створення записів:**
   - **Вікно «Нове навантаження»:** Усувається асиметричний перекіс полів. Вікно отримує дворівневу структуру:
     - Верхній рівень: симетричні парні стовпчики (Предмет + Викладач, Тип занять + Кількість годин).
     - Нижній рівень: повноширинний блок вибору груп із вбудованим пошуковим фільтром та сіткою чекбоксів для мультиселекту потоків.
   - **Вікно «Новий період»:** Небезпечна кнопка скидання `Очистити все` замість тьмяно-червоного кольору набуває вигляду акуратного текстового посилання поруч із заголовком секції груп.
   - **Модальні вікна простих довідників:** Форми додавання груп, викладачів та аудиторій звужуються з нераціональних 800px до пропорційних `420px`.

## 5. Вимоги до мобільної адаптації адмін-панелі

### 5.1. Ліквідація конфліктів плаваючих елементів (FAB)
- На екрані «Навчальне навантаження» кругла плаваюча кнопка додавання `+` (FAB) у правому нижньому куті на смартфонах перекривала іконки видалення та перегляду останніх карток списку.
- **Вимога:** Плаваючий FAB повністю ліквідується. Кнопка створення сутності переноситься у статичний фіксований заголовок сторінки під назвою розділу у вигляді кнопки `+ Додати навантаження` (за загальним стандартом розділів «Версії» та «Періоди»).

### 5.2. Безпека сенсорного скролу в картках (Touch Protection)
- У мобільних списках карток розділів «Періоди», «Версії» та «Історія публікацій» широкі червоні кнопки `Видалити` та `Відкотити` розташовувалися в правій нижній чверті картки — саме в зоні природного руху великого пальця при вертикальному прокручуванні сторінки, що спричиняло випадкові видалення.
- **Вимога:**
  - Головна безпечна дія (`Відкрити`, `Деталі`, `Показати зміни`) займає повну домінуючу ширину нижнього блоку картки.
  - Деструктивна операція виноситься в окрему нейтральну кнопку-іконку розміром `44×44px` у верхній кут картки або ховається у контекстне меню `⋯` з обов'язковим запитом на підтвердження дії через спливаючий діалог.

### 5.3. Розвантаження зони першого екрана (Above the fold) в адмінці розкладу
У поточному інтерфейсі перший екран смартфона був повністю зайнятий службовими описами та великими кнопками, через що диспетчер не бачив жодної пари без скролу.

```
+------------------------------------------+
|  [≡] ДФКР Адмін            [🟢 1] [⋯]   |
|------------------------------------------|
|  Сітка розкладу (Заголовок)              |
|  [ Група ▾ ] [ 85                  ]     |
|  [ Понеділок, 19 жовтня           ▾ ]    |
|------------------------------------------|
|  [ 1 ] 08:00 - 09:20                     |
|  Вища математика | ауд. 301 | Іванов     |
|  --------------------------------------- |
|  [ 2 ] 09:30 - 10:50                     |
|  Комп'ютерні мережі | ауд. 204 | Петров  |
|  --------------------------------------- |
|  [ 3 ] 11:00 - 12:20                     |
|  Фізичне виховання | спортзал            |
+------------------------------------------+
```

- **Вимоги до оптимізації:**
  1. Повністю приховується текстовий описовий абзац під заголовком сторінки.
  2. Перемикач вибору `Група / Викладач` та поле введення номера групи компонуються в один компактний горизонтальний рядок висотою `44px`.
  3. Чотири громіздкі кнопки режимів (`Постійний розклад`, `Виховна година`, `Сесія / Події`, `Друк`) прибираються з головного екрана і виносяться у випадаючий список додаткових опцій кнопки дій `⋯ Дії`.
  4. Ліквідується подвійна вкладена рамка в мобільних слотах занять: замість візуального ефекту «картка всередині картки» використовується єдиний лаконічний зовнішній контур із внутрішнім тонким горизонтальним розділювачем `1px`.
  5. **Результат:** На першому екрані смартфона без скролу відображається щонайменше 2.5–3 слоти занять.

### 5.4. Вирівнювання елементів керування та індикаторів
- **Фільтри розділу «Періоди»:** Випадаючі списки вибору статусу та типу періоду вирівнюються строго по єдиній лівій вертикальній осі; підписи (лейбли) фіксуються над полями з однаковим відступом.
- **Модуль «Імпорт розкладу»:** Зелений світловий індикатор онлайн-статусу вирівнюється строго по висоті базової лінії першого рядка тексту `Остання публікація` і не зміщується у міжрядковий простір при масштабуванні шрифтів.

## 6. Критерії приймання робіт (Definition of Done)

Редизайн вважається успішно виконаним та готовим до передачі в експлуатацію за умови виконання всіх наступних критеріїв:

1. **Цілісність типографіки:** Жоден пункт навігаційного сайдбару, заголовок, назва дисципліни чи текст кнопки не обрізається трикрапкою (`ellipsis`) на діапазонах роздільної здатності від `360px` (смартфони) до `1920px+` (десктопні монітори).
2. **Колірна дисципліна:** Червоний колір палітри (`#EF4444`) задіяно виключно для деструктивних операцій (видалення, скасування, помилки валідації). У системі повністю відсутні широкі червоні кнопки створення, додавання обмежень чи нейтрального виходу.
3. **Безпека сенсорного інтерфейсу:** Жоден плаваючий елемент або кнопка швидких дій (FAB) не перекриває інтерактивні елементи списків карток і таблиць на мобільних пристроях. Усі кнопки видалення в картках ізольовані від зон випадкового натискання під час вертикального скролу.
4. **Інформаційна щільність диспетчера:**
   - На мобільному екрані керування розкладом без прокручування видно щонайменше 2.5 слоти навчальних занять.
   - На широкоформатному моніторі (1920×1080) тижнева сітка розкладу повністю вміщує всі робочі пари дня без появи вертикального скролбару сторінки.
5. **Ергономіка редагування:** Процес внесення змін до навчального заняття на ПК (виклик Slide-over Drawer) не перекриває огляд загальної тижневої сітки розкладу групи та викладача.
6. **Доступність (a11y):** Усі інтерактивні контроли мають чіткий контур фокусу для роботи з клавіатури, контрастність шрифтів відносно фону True Black відповідає стандарту WCAG 2.1 AA.
7. **Стабільність версійності:** Картка діючого розкладу (`• ДІЄ ЗАРАЗ`) завжди займає пріоритетну першу позицію в інтерфейсі, вибір версії генератора відбувається в момент підтвердження публікації чернетки.
